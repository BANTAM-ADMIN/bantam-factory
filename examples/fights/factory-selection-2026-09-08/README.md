# Factory selection · fresh work orders

Three additional development/demo tasks, distinct from the eight earlier work
orders. Build a glob path selector with decision receipts, extend a workspace
containment guard, and repair a semantic-version precedence and range checker.
These exercise selection, sandboxing and dependency-resolution responsibilities
a coding factory actually carries; passing a coding task does not automatically
install or promote its candidate into BANTAM production code.

Each work order specifies a pure API and CLI, with five independent acceptance
groups. Starter public tests are protected. Reviewer solutions are never mounted
into contender workspaces. Freeze this kit before running any live contender;
retain every attempt and any rejected protected-file modification.

The graders are mutation-tested: each one is checked to reject the reference
solution once a single named defect is introduced, so a passing score reflects
behavior rather than the shape of the reference implementation.
